# 静态资源托管

用网关把本机目录里的前端页面、脚本、图片等直接提供给访问者。同一套入口可以同时提供接口和页面：`/api` 转到后端，`/` 或 `/assets` 读本地文件。

适合：Vue / React 打包后的 `dist`、活动页、说明文档站点。不适合：把整站大流量静态文件都压在网关一台机器上（请用浏览器缓存或 CDN）。

---

## 能做什么、不能做什么

**能做**

- 访问者打开网关地址，看到的是本机某个目录里的文件
- 和接口路由共用一个网关实例、同一端口
- 需要登录、限流、跨域时，仍用该路由上的认证 / 限流 / 跨域配置
- 前端 history 路由（地址栏是 `/user/profile` 这类没有文件后缀的路径）可以回退到 `index.html`

**不能做**

- 不会列出目录内容（不能当文件浏览器）
- 只处理浏览器的 GET / HEAD，不能用 POST 上传文件
- 不会去对象存储（OSS、MinIO）里取文件；那些请把路由关联到对应服务，走普通转发
- 不会自动同步多台机器上的目录，每台运行网关的机器都要能读到你填的路径

---

## 路径分两层，不要混用

| 你想改什么 | 用哪里 | 会不会改请求地址 |
|------------|--------|------------------|
| 整条链路看到的 URI（日志、后续过滤器、如果还转发也会变） | 路由过滤器里的路径重写 / 前缀剥离 | 会改 `Request.URL` |
| 磁盘上对应哪个文件 | 本页「按路由路径找文件」「查找路径重写」 | 不改请求地址，只改查找 |
| 反向代理拼到上游的路径 | 路由编辑「转发」里的剥离路径前缀、重写路径 | 只影响转发，静态托管不读 |

静态查找按安全边界处理：先锁定网站目录，再按路由相对路径在该目录里找文件，查找路径重写放在最后。过滤器改完后的请求路径 → 本页剥前缀（仅当本页开关打开）→ 锁定网站文件目录（可含 `{v1,v2}`）→ 可选查找路径重写（只改目录内相对路径，不能换根）→ 文件 / 索引 / SPA。

---

## 配置入口

1. 打开控制台：**网关管理** → **路由管理**
2. 左侧选中网关实例
3. 新增一条路由（或使用已有路由）
4. 新增或编辑路由时，**后端**选 **静态资源**（不要选服务代理）
5. 保存后填写网站文件目录；也可在该路由上右键 → **静态资源**

保存静态托管后，按实例的发布方式**重载网关**，配置才会生效。

后端未配置（既没服务也没静态目录）时，这条路由无法工作。

## 推荐场景

### 场景一：整站前端挂在根路径

打包结果在服务器 `D:/www/shop/dist`（Linux 例如 `/var/www/shop/dist`），希望打开 `https://网关地址/` 就是首页。

1. 新增路由：路径 `/`，匹配类型选**前缀匹配**，后端选**静态资源**
2. 打开「静态托管」，填写：

| 项 | 建议值 |
|----|--------|
| 本机根目录 | `D:/www/shop/dist` |
| 剥离路由前缀 | 开 |
| SPA 回退 | 开（Vue/React history 模式） |
| 索引文件 | `index.html` |
| 缓存秒数 | `3600`（静态 js/css 缓存 1 小时；首页仍不缓存） |

访问 `/` 或 `/index.html` 会读到目录里的 `index.html`。访问 `/assets/app.js` 会读到 `dist/assets/app.js`。

### 场景二：页面挂在子路径，接口仍走后端

希望 `https://网关地址/app` 是前端，`https://网关地址/api` 仍转发到服务。

1. 接口路由：路径 `/api`，前缀匹配，关联后端服务（照常）
2. 前端路由：路径 `/app`，前缀匹配，后端选**静态资源**，保存后填写：

| 项 | 建议值 |
|----|--------|
| 本机根目录 | `D:/www/shop/dist` |
| 剥离路由前缀 | **开**（重要） |
| SPA 回退 | 开 |

「剥离路由前缀」打开后：访问 `/app/index.html` 实际读的是根目录下的 `index.html`，而不是 `app/index.html`。关闭的话，网关会去根目录下找 `app/index.html`，目录结构对不上就会 404。

前端自己的路由基准也要配成 `/app`（例如 Vite 的 `base: '/app/'`），否则页面里的 js/css 路径会错。

### 场景三：旧地址映射到新文件

例如以前是 `/old/a.js`，文件已经改到 `new/a.js`。在「查找路径重写」里按行写规则，**从上到下，命中第一条就停止**：

```text
prefix /old /new
exact /favicon.ico /images/favicon.ico
regex ^/v\d+/(.*)$ /$1
```

也可以写成 `/old => /new`，效果和第一行相同。

| 写法 | 含义 | 例子 |
|------|------|------|
| `prefix /旧前缀 /新前缀` | 只替换路径的前一段，不会误伤更长的名字 | `/old/a.js` → 读 `new/a.js`；`/older/a.js` 不动 |
| `exact /完整路径 /目标` | 只有完全一致才换 | `/favicon.ico` → 读 `images/favicon.ico` |
| `regex 表达式 替换` | 按正则替换，可用 `$1` 表示捕获的一段 | `/v2/css/app.css` → 读 `css/app.css` |

重写发生在目录已经锁定之后：先去掉路由前缀并选定网站目录，再改目录内的相对路径。上面场景二里，访问 `/app/old/a.js` 会先锁定 `dist`，再变成 `/old/a.js`，最后按规则读 `new/a.js`。规则不能把请求换到另一个根目录。

### 场景四：多个站点目录共用一条前缀

若干目录只差一段名字（如 `/var/www/app-v1/dist`、`/var/www/app-v2/dist`）时，用一条**前缀路由**加根目录允许名单，不要为每个目录建路由，也不要把路由正则捕获组写进根目录。

1. 路由：匹配选**前缀**，路径例如 `/apps`
2. 静态托管：

| 项 | 建议值 |
|----|--------|
| 网站文件目录 | `/var/www/app-{v1,v2,v3}/dist` |
| 按路由路径找文件 | **开** |
| 单页应用刷新不报错 | 按前端是否 history 路由决定 |
| 查找路径重写 | 空着 |

访问 `/apps/v1ui/user/1`：去掉前缀得到 `v1ui/user/1`，用第一段锁定 `/var/www/app-v1/dist`，再在该目录里找 `v1ui/...`。名单外的第一段会 403。查找路径重写只改已锁定目录内的相对路径，不能换到 `app-v2`。某个目录不能用同一规则表达时，另建一条前缀路由并写死根目录。

### 场景五：登录壳 + 微前端子应用（由 nginx 迁入）

反向代理、方法限制、`%2f` 校验仍由集群 Ingress 处理。登录入口 301/302 可配网关重定向路由。网关只托管本机目录（如 `/data/tomcat`）。静态路由后端选 **静态资源**，HTTP 方法建议 `GET,HEAD`。优先级数值越小越先命中；前缀 `/` 必须最大。

**仍放 Ingress**

| nginx | 放哪里 |
|-------|--------|
| `/logincenter/datahublogin` → 301 `/#/datahublogin` | 网关路由，后端选重定向，状态码 301，目标 `/#/datahublogin` |
| `/logincenter/datahub_workplace` → 302 | 网关路由，后端选重定向，状态码 302，目标 `/#/datahublogin` |
| `if ($request_method !~* GET\|POST\|HEAD)` | Ingress 方法限制 |
| `if ($request_uri ~ "%2f")` | Ingress 拒绝编码斜杠 |

请求直接落到对应目录：打开「按路由路径找文件」，站点根目录用 `{d10,d12}` 按剥前缀后的首段选目录。`/datahub01webVue`、`/datahub01web` 必须用**正则**，只命中允许的子应用；若写成前缀会吃掉 d01/d05 以及名单外路径。不必写查找重写。

**不能一对一搬过来的 location**

| nginx | 原因 | 做法 |
|-------|------|------|
| `try_files /sec/$app$path /wms/$app$path` | 一条路由只能有一个根目录 | 按应用拆成 `/sec`、`/wms` 两条前缀，或每个 `*Vue` 应用一条固定目录 |
| `root .../sce-vdatahub-$project-web` | 禁止用路由正则 `$1` 拼磁盘路径 | 用允许名单 `{d10,d12,...}` |
| `add_header X-*` | 无任意响应头 | 只配跨域与缓存秒数 |

## 表单字段说明

| 字段 | 说明 |
|------|------|
| 本机根目录 | 网关进程能读到的目录。多个目录只差一段名字时写成 `.../app-{v1,v2}/dist`，见场景四。 |
| 剥离路由前缀 | 建议在子路径托管时打开。正则路由剥字面前缀（`^/datahub01webVue/(d10|d12)` → `/datahub01webVue`）。只认本页开关，与路由「转发」里的剥离无关。 |
| SPA 回退 | 打开后：地址没有文件后缀（如 `/user/12`）且磁盘上没有这个文件时，改回 `index.html`，交给前端路由。带 `.js`、`.css` 的缺失文件仍是 404，避免把资源错误当成网页。 |
| 索引文件 | 访问目录（如 `/` 或 `/docs/`）时依次尝试的文件名，多个用逗号分隔。默认 `index.html`。 |
| 查找路径重写 | 可选。目录锁定之后才改目录内相对路径，不能换根。见场景三。 |
| 缓存秒数 | 普通文件告诉浏览器可以缓存多久。HTML、首页、索引、SPA 回退**不会**用这个值。文件名带内容哈希的 js/css（如 `app.a1b2c3d4.js`）会按一年 `immutable` 缓存，不受此秒数限制。填 `0` 表示普通文件也不缓存。 |
| 扩展名白名单 | 留空不额外限制。填写后只提供这些后缀，例如 `.html,.js,.css`。 |
| 单文件上限 | 超过后返回 413。`0` 表示不限制。 |
| 跟随符号链接 | 默认关。打开后链接目标仍必须在根目录内。 |
| 预压缩 | 默认开。磁盘上有同名 `.br` / `.gz` 且浏览器接受时，直接出压缩文件。 |
| 自定义 404 / 403 | 根目录内的页面，例如 `/404.html`。状态码仍是 404/403，不会变成 200。留空则返回 JSON。 |

查找路径重写在表单里按行维护（前缀 / 精确 / 正则），只改文件查找。路由编辑「转发」里的剥前缀和重写路径只在关联了服务时出现，纯静态路由看不到，避免改到反向代理。

访问目录且地址不以 `/` 结尾时，会 301 到带斜杠的地址，避免页面里的相对路径把 js/css 请求打飞。

访问日志和告警按静态流量单独处理，避免一个页面带出几十条 js/css 记录、把 404 告警刷爆：

- **成功命中不写访问日志**：`file` / `index` / `spa` / `redirect`（状态码小于 400）不落库。
- **异常仍写**：404、403、413、405、5xx 会写访问日志，备注为 `static_result=file|index|spa|redirect|404|forbidden|too_large|method`。
- **告警**：静态 4xx 和读文件超时不告警；仅 5xx 仍按实例告警配置发送。日志写入失败告警不受影响。

改请求 URI 用路由过滤器；改文件映射用本页字段。路由「转发」里的剥离 / 重写路径只给反向代理。保存时会校验正则能否编译；根目录如果已经存在，必须是目录。

## 安全与限制（使用时要注意）

- 只能读根目录里面的文件，不能通过 `../` 读到外面。
- 以点开头的路径默认不提供（如 `/.env`、`/.git`），`.well-known` 除外。
- 网关机器上的目录权限、磁盘空间由运维保证；控制台里填的路径必须是**运行网关的那台机器**能访问的路径，不是你自己电脑上的路径（除非网关就跑在你电脑上）。
- 多实例、容器部署时，每台实例都要挂上同一份目录，或改为把文件放到对象存储再走普通转发。

## 配置后不生效？

按下面顺序检查：

1. 是否已按实例**重载 / 发布**网关。只保存控制台、不重载，线上还是旧配置。
2. 根目录是否写在**网关进程所在机器**上，路径是否存在，进程用户是否有读权限。
3. 子路径托管是否打开了「剥离路由前缀」。
4. 路由匹配：前缀 `/app` 才能吃到 `/app/xxx`；精确匹配 `/app` 只吃恰好等于 `/app` 的请求。
5. 库是升级上来的，若保存静态托管报错，需要先执行静态托管表的建表或补列脚本（请管理员处理），再保存并重载。

## 常见问题

| 现象 | 处理 |
|------|------|
| 打开页面是空白或 js 404 | 子路径托管时打开「剥离路由前缀」，并检查前端打包的 `base` 是否与路由路径一致。 |
| 刷新 `/user/1` 变成 404 | 打开「SPA 回退」。 |
| 想看某个 js 却返回了一整页 HTML | 不要对带后缀的资源依赖 SPA；检查文件是否真的在根目录对应位置。 |
| 发版后首页还是旧的 | 正常：首页不走长缓存。强制刷新即可。js/css 若带 hash 文件名，缓存秒数可以设大一些。 |
| 需要登录才能看页面 | 在该路由右键配置「认证」，不要指望静态托管单独做登录。 |
| 文件在 MinIO / OSS | 不要用静态托管。新增服务节点指向存储地址，路由关联该服务。 |

## 和「关联服务」怎么选

| 你的文件在哪 | 怎么配 |
|--------------|--------|
| 网关机器本地目录 | 本页：路由 + 静态托管 |
| 另一台 HTTP 服务 / nginx / OSS | 路由关联服务，走普通转发 |
| 只要把某个端口转到内网（不是网站文件） | 用隧道里的静态映射，不是本功能 |

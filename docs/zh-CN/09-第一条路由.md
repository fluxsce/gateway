# 第一条路由

网关进程起来之后，默认**没有**可转发的路由。`HUB_GW_INSTANCE` 也没有种子数据：控制台实例列表可能是空的。下面用一条前缀路由，把 `http://localhost:8080/httpbin/...` 转到一个 HTTP 后端。

静态站点（本机目录出页面）见 [静态资源托管](./08-静态资源托管.md)。

---

## 前提

1. 进程已启动。健康检查：`curl http://localhost:12003/health`
2. 浏览器打开控制台：`http://localhost:12003/gatewayweb`
3. 默认账号 `admin` / `123456`（登录后改密码）
4. 准备一个网关能访问的 HTTP 后端。下文以 `httpbin.org:80` 为例；内网服务改成实际主机和端口即可

`8080` 是网关数据面（`configs/gateway.yaml` 的 `listen`）。控制台在 `12003`。不要把这两端口混用。

---

## 1. 新建并启动网关实例

侧栏 **网关管理** → **实例管理**。

若列表为空，点 **新建实例**：

| 项 | 建议值 |
|----|--------|
| 实例名称 | `local-dev` |
| 绑定地址 | `0.0.0.0` |
| HTTP 端口 | `8080`（与 `configs/gateway.yaml` 一致） |
| TLS | 关 |

保存后，在该行右键 **启动**。之后每次改路由或代理，再右键 **网关重载**，配置才会进数据面。

只保存、不启动/不重载，`curl :8080` 仍然对不上这条路由。

---

## 2. 加一个静态服务和节点

侧栏 **网关管理** → **代理管理**。

1. 左侧点选刚建的实例（不选实例，右侧列表不会加载）
2. **新增服务**：服务类型选 **静态配置**，名称例如 `httpbin`，其余用默认
3. 在该服务上进入 **节点管理**，新增节点：

| 项 | 建议值 |
|----|--------|
| 协议 | HTTP |
| 主机 | `httpbin.org` |
| 端口 | `80` |
| 启用 | 开 |

内网后端把主机/端口换成真实地址。节点 URL 由表单根据协议、主机、端口生成。

---

## 3. 加一条前缀路由

侧栏 **网关管理** → **路由管理**。

1. 左侧点选同一实例
2. **新增路由**：

| 项 | 建议值 |
|----|--------|
| 路由名称 | `httpbin-prefix` |
| 路由路径 | `/httpbin` |
| 匹配类型 | **前缀匹配** |
| HTTP 方法 | 空（不限制） |
| 优先级 | `100`（数值越小越先命中） |
| 后端 | **服务代理** |
| 关联服务 | 选上一步的 `httpbin` |

精确匹配 `/httpbin` 只吃恰好等于该路径的请求，不会吃 `/httpbin/get`。前缀匹配才会。

3. 回到 **实例管理**，对该实例 **网关重载**

---

## 4. 验证

```bash
curl -i http://localhost:8080/httpbin/get
```

期望 HTTP 200，响应体来自上游。本机浏览器打开同一地址也可以。

Docker Compose 把网关映射到宿主机 **18280**，那时改成 `http://localhost:18280/httpbin/get`。端口对照见 [FAQ](../faq.md)。

---

## 配完不通？

按这个顺序查：

1. 实例是否已 **启动**，改完是否已 **重载**
2. 路由管理和代理管理左侧是否选了**同一个**实例
3. 路由是前缀 `/httpbin`，不是精确匹配
4. 节点协议/主机/端口网关进程能否访问（容器里 `127.0.0.1` 是容器自己，不是宿主机）
5. 先看控制台能打开，再测 `8080`。`12003/health` 只说明控制面活着，不说明数据面已加载这条路由

## 开发环境调试

### VSCode

仓库已有 `.vscode/launch.json`。当前有效配置如下（`mode` 是 `auto`，工作目录是仓库根，环境变量是 `GATEWAY_ENV`）。

**运行主应用程序**

```json
{
  "name": "运行主应用程序",
  "type": "go",
  "request": "launch",
  "mode": "auto",
  "program": "${workspaceFolder}/cmd/app/main.go",
  "cwd": "${workspaceFolder}",
  "env": {
    "GATEWAY_ENV": "development"
  },
  "args": []
}
```

入口是 `cmd/app/main.go`，不是已删除的 `cmd/gateway/main.go`。命令行等价：

```bash
go run cmd/app/main.go --config ./configs
```

进程要从**仓库根**启动，才能读到 `configs/` 和 `scripts/db/`。

不要用已删除的 `cmd/test/debug_sample.go`。

成功后：

- 网关数据面：`http://localhost:8080`
- 控制台 / 健康检查：`http://localhost:12003/health`（`8080` 没有 `/health`）
- 控制台 UI：`http://localhost:12003/gatewayweb`

源码启动时 `web/frontend/dist` 不进 Git，见 [开发指南](./02-快速开始.md)。

### 使用断点

**设置断点：**
- 点击代码行号左侧空白处（出现红点）
- 快捷键：`F9`

**条件断点：**
- 右键点击断点 → 编辑断点 → 添加条件表达式
- 示例：`userId == "123"` 或 `count > 10`

**日志点：**
- 右键点击断点 → 编辑断点 → 添加消息
- 不会暂停程序，只输出日志

### 调试快捷键

| 操作 | Windows/Linux | Mac |
|------|---------------|-----|
| 启动调试 | `F5` | `F5` |
| 继续执行 | `F5` | `F5` |
| 单步执行（不进入函数） | `F10` | `F10` |
| 单步执行（进入函数） | `F11` | `F11` |
| 跳出当前函数 | `Shift+F11` | `Shift+F11` |
| 重启调试 | `Ctrl+Shift+F5` | `Cmd+Shift+F5` |
| 停止调试 | `Shift+F5` | `Shift+F5` |

## 性能分析

### 启用 pprof

配置在 `configs/app.yaml` 的 **`app.pprof`**（不是文件根上的 `pprof.port`）。默认 `enabled: false`。

```yaml
app:
  pprof:
    enabled: true
    listen: ":6060"
```

启动后：`http://localhost:6060/debug/pprof/`

### CPU 性能分析

```bash
# 采集 30 秒 CPU
go tool pprof http://localhost:6060/debug/pprof/profile?seconds=30

# 火焰图：不要占用网关的 8080，改用别的端口
go tool pprof -http=:6061 http://localhost:6060/debug/pprof/profile?seconds=30
```

### 内存分析

```bash
# 查看当前内存使用
go tool pprof http://localhost:6060/debug/pprof/heap

# 生成内存分析报告
go tool pprof -http=:6061 http://localhost:6060/debug/pprof/heap
```

### Goroutine 分析

```bash
# 查看所有 goroutine
curl http://localhost:6060/debug/pprof/goroutine?debug=2

# 分析 goroutine 泄漏
go tool pprof http://localhost:6060/debug/pprof/goroutine
```

## 常见问题排查

### 1. 应用无法启动 / 连不上库

默认**不是 MySQL**。`configs/database.yaml` 里 `database.default` 是 `sqlite_main`，库文件 `./scripts/data/gateway.db`。

**SQLite（默认）**

1. 进程工作目录是否为仓库根（相对路径 `./scripts/data/gateway.db` 才有效）
2. Windows 是否已装 C 编译器（CGO）。`gcc --version` 失败见 [FAQ](../faq.md)
3. `scripts/data/` 是否可写；`enable_script_initialization: true` 时启动会跑 `scripts/db/sqlite`

**改成了 MySQL 才查这些**

```bash
# 确认 YAML 里 default 已是 mysql，且 connections.mysql.enabled: true
# 不要写成 type/host 那种旧结构
mysql -h 127.0.0.1 -P 3306 -u root -p
```

健康检查始终打控制面：

```bash
curl http://localhost:12003/health
```

---

### 2. 内存泄漏

**问题现象：**
- 内存持续增长
- OOM (Out of Memory) 错误

**排查步骤：**

1. **查看内存使用**
   ```bash
   # 查看进程内存使用
   ps aux | grep gateway
   
   # 使用 top 命令
   top -p $(pgrep gateway)
   ```

2. **分析内存快照**
   ```bash
   go tool pprof http://localhost:6060/debug/pprof/heap
   ```

3. **查看 goroutine 数量**
   ```bash
   curl http://localhost:6060/debug/pprof/goroutine?debug=1 | grep goroutine
   ```

---

### 3. 性能问题

**问题现象：**
- 响应时间慢
- CPU 使用率高

**排查步骤：**

1. **查看 CPU 使用**
   ```bash
   # 查看进程 CPU 使用
   ps aux | grep gateway
   
   # 使用 top 命令
   top -p $(pgrep gateway)
   ```

2. **CPU 性能分析**
   ```bash
   go tool pprof -http=:6061 http://localhost:6060/debug/pprof/profile?seconds=30
   ```

3. **查看慢查询日志**
   ```bash
   grep "slow query" logs/debug.log
   ```

---

### 4. 网络连接问题

**问题现象：**
```
Error: dial tcp: connect: connection refused
```

**排查步骤：**

1. **检查端口监听**

控制台和健康检查在 **12003**，网关数据面在 **8080**。先确认你在测哪一端。

```bash
curl http://localhost:12003/health
# Windows: netstat -ano | findstr "8080 12003"
ss -tulpn | grep -E '8080|12003'
```

2. **测试端口连通性**
   ```bash
   telnet localhost 8080
   nc -zv localhost 8080
   ```

3. **检查防火墙规则**
   ```bash
   # Linux
   iptables -L -n

   # 检查 SELinux
   getenforce
   ```

---

### 5. 配置文件问题

**问题现象：**
```
Error: failed to load config file
```

**排查步骤：**

1. **检查配置文件是否存在**
   ```bash
   ls -la configs/
   ```

2. **验证 YAML 语法**
   ```bash
   # 使用 yamllint
   yamllint configs/database.yaml

   # 或使用 Python
   python -c "import yaml; yaml.safe_load(open('configs/database.yaml'))"
   ```

3. **检查文件权限**
   ```bash
   ls -l configs/
   chmod 644 configs/*.yaml
   ```

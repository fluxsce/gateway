## 🔧 错误处理机制

### 标准错误处理

Gateway 使用 Go 标准的错误处理方式：

```go
import (
    "errors"
    "fmt"
)

// 创建简单错误
err := errors.New("配置文件不存在")

// 格式化错误
err := fmt.Errorf("无法连接到数据库: %s", dbHost)

// 包装错误
if err != nil {
    return fmt.Errorf("初始化失败: %w", err)
}
```

### 错误检查

```go
import "errors"

// 检查错误类型
if errors.Is(err, os.ErrNotExist) {
    // 文件不存在
}

// 检查错误值
var pathError *os.PathError
if errors.As(err, &pathError) {
    // 处理路径错误
}
```

## 🎯 HubError 使用

Gateway 提供了增强的错误处理机制 `huberrors`，可以创建带有精确位置信息的错误。

### 功能特点

1. ✅ 自动捕获错误发生的**精确文件名、行号和函数名**
2. ✅ 与日志系统深度集成，提供完整的错误栈信息
3. ✅ 支持原始错误的包装，保留完整的错误链
4. ✅ 错误信息格式化支持，与 `fmt.Errorf` 兼容

### 导入包

```go
import (
    "gateway/pkg/utils/huberrors"
)
```

Go module 路径是 `gateway`（见仓库根 `go.mod`），不是 `github.com/fluxsce/gateway/...`。

### 创建新错误

```go
// 创建带位置信息的错误（类似 errors.New）
err := huberrors.NewError("发生了错误")

// 支持格式化（类似 fmt.Errorf）
err := huberrors.NewError("无法解析配置: %s", configName)

// 错误输出示例：
// 无法解析配置: database.yaml (at /path/to/file.go:25 in package.function)
```

### 包装已有错误

```go
// 包装已有错误，添加上下文信息
originalErr := someFunction()
wrappedErr := huberrors.WrapError(originalErr, "操作失败")

// 支持格式化
wrappedErr := huberrors.WrapError(originalErr, "处理 %s 时失败", resourceName)

// 错误输出示例：
// 处理 users 时失败 (at /path/to/file.go:42 in package.function): 原始错误信息
```

### 与日志系统集成

```go
err := huberrors.NewError("数据库连接失败")
logger.Error("系统启动失败", err)
```

**日志输出将包含：**
- 错误消息
- 错误类型
- 完整的文件路径、行号和函数名
- 堆栈跟踪

## HTTP 错误响应

控制台 API 的 JSON 在 `web/utils/response/response.go`，**不是** `{code, message, details}`。字段名 `oK` 是历史兼容（JSON tag `oK`）。

```go
type JsonData struct {
    OK            bool        `json:"oK"`
    State         bool        `json:"state"`
    BizData       string      `json:"bizData"`
    ExtObj        interface{} `json:"extObj"`
    PageQueryData string      `json:"pageQueryData"`
    MessageId     string      `json:"messageId"`
    ErrMsg        string      `json:"errMsg"`
    PopMsg        string      `json:"popMsg"`
    ExtMsg        string      `json:"extMsg"`
}
```

成功：`SuccessJSON` / `response.Success` → `oK: true`，业务对象在 `bizData`（字符串里再套一层 JSON）。

失败：`ErrorJSON` → 默认 **HTTP 仍是 200**，`oK: false`，文案在 `errMsg`。`MarkBizError` 会在 gin 上下文打标，给审计用。需要非 200 时给 `ErrorJSON` 传 `status`。

```go
response.SuccessJSON(c, data, messageId)
response.ErrorJSON(c, "userId 不能为空", messageId)
```

数据面（访问者打到 `:8080` 的网关）用的是 HTTP 状态码本身（404/502/504 等），不要和控制台这份 `JsonData` 混在一起。

### 数据面常见 HTTP 状态码

| 状态码 | 说明 | 使用场景 |
|--------|------|----------|
| **400** | Bad Request | 请求参数错误 |
| **401** | Unauthorized | 未认证 |
| **403** | Forbidden | 无权限 |
| **404** | Not Found | 资源不存在 |
| **409** | Conflict | 资源冲突 |
| **429** | Too Many Requests | 请求过于频繁 |
| **500** | Internal Server Error | 服务器内部错误 |
| **502** | Bad Gateway | 后端服务错误 |
| **503** | Service Unavailable | 服务不可用 |
| **504** | Gateway Timeout | 网关超时 |

不要在控制台 handler 里再发明一套 `ErrorResponse{Code, Message, Details}`。业务失败走 `response.ErrorJSON`。

## ✅ 最佳实践

### 1. 在错误源头使用 NewError

在错误最初发生的地方使用 `NewError`，确保捕获最精确的位置信息。

```go
func readConfig(path string) (Config, error) {
    data, err := os.ReadFile(path)
    if err != nil {
        // ✅ 在源头包装错误
        return nil, huberrors.WrapError(err, "读取配置文件失败: %s", path)
    }
    
    var config Config
    if err := json.Unmarshal(data, &config); err != nil {
        // ✅ 在源头包装错误
        return nil, huberrors.WrapError(err, "解析配置文件失败: %s", path)
    }
    
    if !config.IsValid() {
        // ✅ 创建新错误
        return nil, huberrors.NewError("配置无效: %s", path)
    }
    
    return config, nil
}
```

### 2. 在中间层使用 WrapError

向上传递错误时，使用 `WrapError` 添加上下文信息。

```go
func initDatabase() error {
    config, err := readConfig("database.yaml")
    if err != nil {
        // ✅ 包装错误，添加上下文
        return huberrors.WrapError(err, "初始化数据库失败")
    }
    
    db, err := connectDB(config)
    if err != nil {
        // ✅ 包装错误，添加上下文
        return huberrors.WrapError(err, "连接数据库失败")
    }
    
    return nil
}
```

### 3. 保持错误消息简洁明了

错误消息应该清晰描述发生了什么，不要包含过多的技术细节。

```go
// ✅ 好的错误消息
err := huberrors.NewError("配置文件不存在")
err := huberrors.NewError("数据库连接失败")
err := huberrors.NewError("用户名或密码错误")

// ❌ 不好的错误消息
err := huberrors.NewError("os.Open() returned error: file not found at line 42")
err := huberrors.NewError("SQL error 1045: Access denied for user 'root'@'localhost'")
```

### 4. 避免重复创建错误

如果已经有带位置信息的 `HubError`，使用 `WrapError` 而不是创建新错误。

```go
// ✅ 正确做法
func processUser(id string) error {
    user, err := getUser(id)
    if err != nil {
        return huberrors.WrapError(err, "处理用户失败")
    }
    // ...
}

// ❌ 错误做法
func processUser(id string) error {
    user, err := getUser(id)
    if err != nil {
        return huberrors.NewError("处理用户失败: %v", err) // 丢失了原始错误的位置信息
    }
    // ...
}
```

### 5. 记录错误日志

在适当的位置记录错误日志，但避免重复记录。

```go
// ✅ 在最外层记录错误
func main() {
    if err := initDatabase(); err != nil {
        logger.Error("应用启动失败", err)
        os.Exit(1)
    }
}

// ❌ 在每一层都记录错误（会导致日志重复）
func initDatabase() error {
    config, err := readConfig("database.yaml")
    if err != nil {
        logger.Error("读取配置失败", err) // ❌ 不要在这里记录
        return err
    }
    // ...
}
```

## 🐛 常见错误场景

### 1. 配置文件错误

```go
func loadConfig(path string) (*Config, error) {
    // 检查文件是否存在
    if _, err := os.Stat(path); os.IsNotExist(err) {
        return nil, huberrors.NewError("配置文件不存在: %s", path)
    }
    
    // 读取文件
    data, err := os.ReadFile(path)
    if err != nil {
        return nil, huberrors.WrapError(err, "读取配置文件失败: %s", path)
    }
    
    // 解析 YAML
    var config Config
    if err := yaml.Unmarshal(data, &config); err != nil {
        return nil, huberrors.WrapError(err, "解析配置文件失败: %s", path)
    }
    
    // 验证配置
    if err := config.Validate(); err != nil {
        return nil, huberrors.WrapError(err, "配置验证失败: %s", path)
    }
    
    return &config, nil
}
```

### 2. 数据库错误

```go
func getUser(id string) (*User, error) {
    var user User
    
    // 查询数据库
    err := db.QueryRow("SELECT * FROM users WHERE id = ?", id).Scan(&user)
    
    // 处理不同类型的错误
    if err != nil {
        if errors.Is(err, sql.ErrNoRows) {
            return nil, huberrors.NewError("用户不存在: %s", id)
        }
        return nil, huberrors.WrapError(err, "查询用户失败: %s", id)
    }
    
    return &user, nil
}
```

### 3. HTTP 请求错误

```go
func callExternalAPI(url string) ([]byte, error) {
    // 发起请求
    resp, err := http.Get(url)
    if err != nil {
        return nil, huberrors.WrapError(err, "HTTP 请求失败: %s", url)
    }
    defer resp.Body.Close()
    
    // 检查状态码
    if resp.StatusCode != http.StatusOK {
        return nil, huberrors.NewError("HTTP 请求失败: %s, 状态码: %d", url, resp.StatusCode)
    }
    
    // 读取响应
    body, err := io.ReadAll(resp.Body)
    if err != nil {
        return nil, huberrors.WrapError(err, "读取响应失败: %s", url)
    }
    
    return body, nil
}
```

### 4. 参数验证错误

```go
func createUser(req *CreateUserRequest) error {
    // 验证用户名
    if req.Username == "" {
        return huberrors.NewError("用户名不能为空")
    }
    if len(req.Username) < 3 || len(req.Username) > 20 {
        return huberrors.NewError("用户名长度必须在 3-20 之间")
    }
    
    // 验证密码
    if req.Password == "" {
        return huberrors.NewError("密码不能为空")
    }
    if len(req.Password) < 6 {
        return huberrors.NewError("密码长度不能少于 6 位")
    }
    
    // 验证邮箱
    if req.Email == "" {
        return huberrors.NewError("邮箱不能为空")
    }
    if !isValidEmail(req.Email) {
        return huberrors.NewError("邮箱格式不正确")
    }
    
    return nil
}
```

### 5. 并发错误处理

```go
func processItems(items []Item) error {
    var wg sync.WaitGroup
    errChan := make(chan error, len(items))
    
    for _, item := range items {
        wg.Add(1)
        go func(item Item) {
            defer wg.Done()
            if err := processItem(item); err != nil {
                errChan <- huberrors.WrapError(err, "处理项目失败: %s", item.ID)
            }
        }(item)
    }
    
    wg.Wait()
    close(errChan)
    
    // 收集所有错误
    var errs []error
    for err := range errChan {
        errs = append(errs, err)
    }
    
    if len(errs) > 0 {
        return huberrors.NewError("批量处理失败，共 %d 个错误", len(errs))
    }
    
    return nil
}
```
